# 质检规则说明

系统内置 **32 条** 质检规则，覆盖三个维度：

| 类别 | 规则数 | 关注点 |
|------|--------|--------|
| 执行规范 | 12 | 是否按流程操作 |
| 销售技巧 | 12 | 是否促成成交 |
| 服务态度 | 8 | 是否让客户满意 |

每条规则支持三种触发方式：

- **keyword**：关键词匹配
- **timing**：时间窗口检测
- **ai**：调用大模型判定（需要 LLM_API_KEY）

每条违规按严重程度扣 4 个梯度分：

- 第一次触发：扣 first_penalty
- 第二次：扣 second_penalty
- 第三次：扣 third_penalty
- 第四次及以上：扣 fourth_penalty

## 配置自定义规则

通过后台 `/admin/rules` 或 API `POST /api/rules/` 添加规则。

每条规则的 config 字段：

```json
// keyword 类型
{
  "keywords": ["关键词1", "关键词2"]
}

// timing 类型
{
  "timeout_minutes": 30,
  "min_interactions": 3
}

// ai 类型
{
  "prompt_hint": "判断客服是否..."
}
```

## AI 判定规则的工作原理

1. Celery Worker 接收到 evaluate_conversation 任务
2. 任务收集该对话所有消息，拼成 prompt
3. 调用 LLM（DeepSeek/Qwen/OpenAI），要求输出 JSON `{triggered: bool, evidence: str, severity: int}`
4. 若 triggered=true，创建 Violation 记录，evidence_text 存 LLM 给出的证据
5. LlmCall 表记录调用耗时、token 数、错误信息

LLM 调用结果会被缓存（按消息哈希），相同对话只调一次。
